# KeyRing v0.1.6 完成计划

创建日期：2026-09-14；更新日期：2026-10-04。状态：功能已进入实现与回归阶段，尚未正式发布。下方“当前基线”记录开始开发时的情况。

## 1. 当前基线

- 当前分支 `main`，HEAD `a18821e`；检查时工作目录干净。
- 源码版本与 `/Applications/key_ring.app` 的安装版本均为 `0.1.6+2003`；安装包版本一致不代表构建内容完全一致。
- 已有工作区、分组、选择性局域网同步、自定义保密项，以及相关迁移和同步测试。
- 现有文件导入仅支持 KeyRing JSON；合并依赖条目 ID 和更新时间，不能直接用于 Chrome CSV 的重复导入。
- 工作区切换直接更新选中 ID，没有验证。当前应用解锁走系统认证；`SecureKeyService` 的主密码逻辑没有接入此流程。
- 详情已有网址、备注和保密项展示，但网址单行省略；编辑后会弹出详情页返回首页。备注缺失的实际原因仍需用合成记录复现，不能仅凭源码判断已修好。
- 添加保密项默认名称为空、类型为普通文本，没有“密码2、密码3”的快捷行为。
- macOS 产品名、Xcode 引用与发布脚本仍使用 `key_ring.app`。README 版本和既有设计文档的实现状态已落后。
- 桌面快捷填充显示面板前调用应用级 `activateSelf()`；macOS 对应 `NSApp.activate`。应用锁定时，快捷键入口还会直接显示、还原并聚焦主窗口。这两条路径都需要纳入“只打开快捷面板”的调整。

## 2. 实施选择

Chrome 接入按先前说明实现为 CSV 导入与重复导入。2026-10-04 用户补充：工作区既可使用系统解锁，也可设置自定义密码；应用退到后台两分钟后锁定。

| 选择 | 推荐方案 | 另一种方案的影响 |
| --- | --- | --- |
| Chrome 同步方式 | Chrome 导出 CSV → KeyRing 本地导入，支持重复导入去重和冲突处理 | 持续自动同步需要单独验证浏览器接入能力、权限、增量事件和安装方式，不能把 CSV 导入验收当成自动同步完成 |
| 工作区切换验证 | 每个工作区可选择系统验证或独立自定义密码，也可关闭额外验证 | 系统验证使用设备支持的指纹、面容或设备密码 |

工作区验证细则：默认关闭，各设备分别设置；进入受保护工作区时验证，离开后再次进入需要重验，后台满两分钟锁定和重启清除授权。配置不随 JSON 或局域网同步传输。改变或关闭保护需要先通过当前验证，启用系统验证时需实际认证成功。

当前条目数据库是普通 SQLite；本计划中的工作区密码提供应用内访问验证。独立工作区加密需要另外设计密钥、数据库与跨设备同步迁移，不能将访问验证描述为独立加密。

## 3. 六项需求的实现与验收

### 3.1 Chrome 账号密码导入

用户流程：导入数据 → 从 Chrome 导入 → 查看导出指引 → 选择 CSV → 选择目标工作区／分组 → 预览和处理冲突 → 确认导入 → 查看结果。

实现内容：

- 新增专用 CSV 解析与导入计划服务，复用仓库的事务写入能力；不套用 JSON 的 ID／时间戳合并规则。
- 识别 `name/url/username/password`，兼容可选 `note/notes`；名称缺失时按网址生成可编辑名称。保留密码原始字符和多行备注。
- 支持 UTF-8 BOM、CRLF、引号、逗号、转义双引号、字段内换行、空用户名；畸形格式和缺少必要列给出明确错误。
- 按“目标工作区 + 完整网址的保守规范化结果 + 用户名”找匹配项，不能只按网站名或域名匹配。多个匹配项交给用户选择。
- 同一文件内及再次导入的完全重复记录跳过；已有记录内容不同时，默认保留本地，用户可选择更新或另存。CSV 没有可靠更新时间，不能把导入时间当成来源更新依据。
- 同一网站的不同账号独立保存；处理现有的工作区内标题唯一限制，预览最终名称，不能静默覆盖。
- 更新时保留 KeyRing 的收藏、分组、自定义保密项以及来源缺失的备注等字段。用户确认前不落库，写入前重新核对匹配状态与工作区授权。
- 预览默认隐藏密码，错误提示与日志不打印记录内容。导入完成说明源 CSV 含明文密码，由用户自行处理源文件。

主要落点：`lib/screens/import/import_hub_sheet.dart`、新增 Chrome 导入页面和解析／计划服务、`lib/services/password_repository.dart`。

验收：同站多账号不合并；重复导入不增加条目；冲突不自动覆盖；特殊字符密码和多行备注逐字保留；取消预览没有写入；导入后详情与后续 LAN 同步保留字段。

依据：Google 官方提供密码管理器导出入口，见 [Chrome 密码导入导出说明](https://support.google.com/chrome/answer/13068232?co=GENIE.Platform%3DDesktop&hl=en)。普通扩展的公开能力可查 [Chrome Extensions API reference](https://developer.chrome.com/docs/extensions/reference/api)；持续读取内置密码库的能力仍需独立验证。

### 3.2 工作区切换密码

用户流程：管理工作区 → 编辑工作区 → 本机访问密码 → 设置／修改／关闭。设置需要重复输入；修改和关闭需要验证现有密码。

实现内容：

- 新建工作区访问验证服务，统一处理本机配置、密码验证、授权状态、失败冷却和授权失效。
- 使用系统安全存储保存带独立盐及参数的密码验证信息，选择经过验证的密码派生实现，不保存明文密码。
- 工作区菜单展示锁状态；验证取消或失败时留在原工作区，目标记录不得提前显示。
- 受保护的默认工作区在启动／应用解锁后也要验证；验证过程中应用锁定，迟到的成功回调不能恢复旧授权。
- 详情、编辑、移动归属、导入目标、导出和手动同步选择都使用统一授权检查。受保护工作区的导出／发送需要先验证，不能借“全量导出”绕过入口。
- 桌面快速填充按授权状态过滤候选，并在真正填充前再次检查；锁定时清理已打开面板的旧候选。
- Android 与 iOS 的原生自动填充现在直接读数据库，必须一起处理。本期建议受保护工作区不参与这两个系统扩展的自动填充；iOS 共享容器不再保留其旧条目副本。独立密码验证页接入扩展可另行扩展。
- 原生入口拿不到可靠访问配置时不展示受保护数据；本机锁配置不进入已有导出和同步模型。删除工作区时清理对应本机配置。

主要落点：新增工作区访问服务、`workspace_management_screen.dart`、`home_screen.dart`、`edit_item_screen.dart`、`detail_screen.dart`、`app_lock_state.dart`、`quick_fill_host.dart`，以及 Android/iOS 自动填充和共享副本逻辑。

验收：正确／错误／取消、设置／改密／关闭、重启／退后台／切换离开后重进均符合约定；快速填充、导出、移动与原生自动填充不能绕过验证；未设置密码的工作区保持原操作体验；一台设备的锁配置不被另一台设备同步覆盖。

### 3.3 详情完整显示备注与网址

- 用包含长网址、多行中文备注的合成记录，验证新增 → 保存 → 首页点击 → 详情 → 编辑 → 返回的完整路径。
- 网址在详情中可完整换行、选择和复制；有备注时完整显示多行内容，无内容时显示“未填写”。
- 编辑保存后留在详情页并更新数据，返回首页时仍正确通知刷新；重新进入详情时恢复密码掩码。
- 修正 `PasswordItem.copyWith(url: null)` 当前无法清空旧网址的语义，并覆盖保存、导入与同步后的空值行为。
- 若备注缺失发生在保存、旧数据或导入路径，按复现结果修复对应入口，避免仅调整展示后宣布完成。

主要落点：`lib/screens/detail_screen.dart`、`lib/screens/edit_item_screen.dart`、`lib/models/password_item.dart`。

验收：长网址不省略，多行备注完整；清空与重新填写网址／备注能持久化；编辑返回显示最新值；macOS 窄窗口与移动端布局正常。

### 3.5 密码2、密码3及自定义名称

- 在主密码旁添加“添加密码”入口，新增字段立即显示，默认类型为 password、默认掩码。
- 自动命名“密码2”“密码3”……，选择未被占用的编号；删除或改名不改变其它字段名称，不能产生重名。
- 每项支持自定义名称、显示／隐藏、复制、生成密码和删除；保留现有其它类型的保密项功能。
- 继续使用 `customFields` 和 `SecretField`，保留编辑前的字段 ID，不新增 `password2/password3` 固定数据库列。
- 空名称与重名给出明确提示；密码值不做自动 trim。新增密码与原主密码都要覆盖首尾空格的保真行为。
- 详情、JSON 导入导出、同版本 LAN 同步使用现有字段模型完整传递；旧协议不支持附加字段时继续明确兼容限制。

主要落点：`lib/screens/edit_item_screen.dart`、`lib/screens/detail_screen.dart`、`lib/models/secret_field.dart`。

验收：连续添加得到密码2／密码3；改为“交易密码”等自定义名称后保存、重开、导出再导入仍一致；各项独立显示与复制；删除后再添加不重名；旧记录兼容。

### 3.6 PC 快捷键只显示快捷面板

已确认需求：在电脑上使用快速填充快捷键时，只打开快捷键对应的搜索／选择面板，不唤起 KeyRing 主界面。覆盖 macOS 和 Windows 的现有桌面快捷填充入口。

- 快捷键仅显示并聚焦快捷面板；主窗口保持原有隐藏、最小化或后台状态，不闪现、不还原、不抢到前台。
- 调整应用级激活与子窗口聚焦顺序，使用平台支持的面板／指定窗口激活方式；不能简单删除激活调用后导致搜索框无法输入。
- 记录按下快捷键时的目标应用／窗口。面板可立即输入搜索，支持方向键选择、Enter 填充、Esc 关闭和再次按快捷键收起；填充或主动取消后将焦点交还原目标。用户主动点击其它应用造成失焦时收起面板，不反向抢焦点。
- 应用或工作区锁定时，验证在快捷面板或系统认证弹窗内完成；验证成功后继续显示候选。取消或失败时不展示受保护数据，也不自动打开主界面。认证过程不能把原填充目标替换为 KeyRing 或系统认证窗口。
- 填充错误与重试提示保留在快捷面板内，错误恢复路径同样不得唤起主窗口。
- 主窗口仅在用户主动选择“打开 KeyRing”等入口时显示；快捷键内部流程不得调用主窗口显示／还原逻辑。

主要落点：`lib/main.dart`、`lib/quick_fill/quick_fill_host.dart`、`lib/quick_fill/window_entry.dart`、`lib/services/foreground_app_service.dart`、`macos/Runner/AppDelegate.swift` 和 Windows 原生窗口逻辑。与第 3.2 节共用授权检查及验证服务。

验收：主窗口隐藏、最小化、位于其它应用后方时，首次及反复按快捷键均只显示快捷面板；搜索框可直接输入；填充、Esc、重复快捷键、失焦及失败重试行为正确；锁定后验证仍不唤起主界面；在多显示器和全屏应用场景实测窗口与焦点行为。macOS／Windows 分别记录实测结果。

## 6. 2026-10-04 界面反馈设计

- 首页条目拆成独立组件：标题与收藏、用户名、主密码、密码2／密码3与其它自定义项逐行排列；右侧统一 44×44 的显示和复制按钮槽位，长名称和值自适应。每个隐私项独立掩码，记录更新或授权变化后恢复隐藏。
- 工作区管理使用独立的操作区与拖拽手柄，关闭 ReorderableListView 的默认拖拽手柄，避免它覆盖删除按钮。窄窗口将次要操作收进菜单。
- 后台计时由应用根层管理，覆盖所有路由及主窗口隐藏／最小化；短暂切出不锁，满两分钟锁定。返回前台额外核对实际离开时长。快捷面板交互期间视为使用中，关闭后重新计时。
- 工作区访问设置提供“无需额外验证／系统验证／自定义密码”。主界面与快捷面板复用验证服务；失败、取消、全局锁定或过期回调均不能授予访问权限。
- Agent Bridge 经用户授权使用 Claude Code、智谱 GLM-5.3 high，仅编写两个独立界面组件及其测试；主代理完成接入、授权逻辑和本地验收。调用不包含真实密码库。
